# Quality Checklist

## Product Fit

- The first screen is an actual SaaS product surface, not a landing page.
- The UI matches the requested domain and user workflow.
- Primary and secondary actions are clear.
- Navigation reflects a plausible product information architecture.
- Data, labels, and states are realistic enough to understand the workflow.

## Layout

- Desktop layout uses space efficiently without oversized hero-style composition.
- Mobile layout remains usable without overlapping content.
- Sidebars, tables, cards, and panels have stable dimensions.
- Long text does not overflow buttons, chips, table cells, nav items, or cards.
- No card is nested inside another card.

## Components

- Forms have labels, validation states, help text where needed, and clear save/cancel behavior.
- Tables have useful columns, sort/filter affordances, row actions, and empty/loading states where relevant.
- Tabs, filters, menus, and toggles have active/selected/disabled states.
- Destructive actions are visually separated and confirmed.

## Accessibility

- Page has semantic landmarks: header/nav/main/aside where appropriate.
- Interactive controls are keyboard reachable and have visible focus.
- Icon-only buttons have accessible labels or visible tooltips.
- Color contrast is sufficient for text and status indicators.
- Status is not communicated by color alone.
- Touch targets are practical on mobile.

## Visual Finish

- Palette is restrained, not dominated by one hue family.
- Typography scale fits the UI density.
- Spacing is consistent and based on a small token scale.
- Borders, shadows, and radii are subtle and consistent.
- The design looks like a production SaaS tool, not a generic template.
